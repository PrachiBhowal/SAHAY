# Gamosa-inspired border asset

Responds to Prachi's `NER_Visual_Assets_Handoff.docx` follow-up: *"finalize
a production-safe Gamosa-inspired asset (original illustration or
licensed source), not the raw search-result images used for direction."*

## What this is
- `gamosa-border.svg` — an **original**, hand-designed geometric pattern
  (thin diamond-and-line repeat). Not traced or copied from any
  reference image found during research — see the provenance comment
  at the top of the SVG.
- Uses the existing palette (`--color-terracotta`, `--color-brown`,
  `--color-ochre`) instead of traditional Gamosa red-on-white, so it
  reads as "inspired by" rather than a reproduction.
- `GamosaBorder.jsx` / `.css` — a React wrapper so nobody has to
  hand-write `background-image` CSS per screen.

## How to put the files together

1. **Copy both files into your project**, keeping them in the same
   folder together (the CSS references the SVG by relative path):
   ```
   your-project/
     src/
       components/
         GamosaBorder/
           gamosa-border.svg
           GamosaBorder.jsx
           GamosaBorder.css
   ```

2. **Import and use it** wherever you need the strip:
   ```jsx
   import { GamosaBorder } from './components/GamosaBorder/GamosaBorder';

   function LoginCard() {
     return (
       <div className="login-card">
         <GamosaBorder mode="strip" />
         {/* existing login form content */}
         <GamosaBorder mode="strip" />
       </div>
     );
   }
   ```

3. **For a corner accent** (Anvi, on game screens — never over the
   actual gameplay area):
   ```jsx
   <GamosaBorder
     mode="corner"
     style={{ position: 'absolute', top: 0, right: 0, width: 96, pointerEvents: 'none' }}
   />
   ```
   Make sure the parent container has `position: relative` so the
   absolute positioning is scoped to the card, not the whole page.

4. **This depends on `tokens.css` already being loaded** in your app
   (it's part of the design-system module from Day 1) — the SVG's
   colors are hardcoded hex right now, not CSS variables, because SVG
   `background-image` files can't read CSS custom properties from the
   consuming page. If we ever change the palette, this SVG has to be
   regenerated by hand — flagging that as a known limitation, not
   something to silently fix later.
